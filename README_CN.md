# 中文使用说明

主入口为[SKILL.md](SKILL.md)。本仓库是一套让Agent执行的写作Skill；素材和结果放在独立项目目录，仓库中不保存私稿。

## 第一次使用

把原稿位置和这次目标告诉Agent。例子：

```text
读取SKILL.md。素材是中文都市短剧DOCX，先分析全稿，给三个改写方向，暂不写正文。
```

Agent先确认可访问的素材、载体和任务范围，保留原件，读取全稿后提炼结构。已有答案不反复询问；真正读不到的文件或不能决定的方向才需要补充。

小说、短剧、审稿和修订沿用同一入口，只读取对应参考。短剧不自动转小说，不默认面向海外，不强制原章减半或世界扩张。

## 按阶段继续

```text
选方向A。人物、地点和关键道具都要更名，先完成故事蓝图和分集大纲。
```

```text
继续完成全部正文，去掉机械感。内部先检验开篇和不同单元，发现问题直接修正后继续。
```

```text
审稿，重点看因果、感情推进、单元重复和终局对抗。先给定位到具体集数的意见。
```

```text
按已确认意见修第二版，保留第一版，修改完成后复查并重新导出。
```

用户授权的阶段是边界。“先分析”不会自动变成写全稿；后来明确“完成正文”后，旧的暂不写限制也不能阻止继续。内部检查不新增用户批准节点。

## 项目中会保留什么

[项目接入](references/project-setup.md)记录约定和原稿范围；[状态与交付](references/state-and-delivery.md)给出轻量目录示例。已有工程沿用有效布局，不强制迁目录。

最重要的是当前约定、进度入口、新设定／命名、实际正文、连续性变化与审稿问题。大修留存旧版，区分当前工作稿与已交付版。未完成的新版本不能标成全稿交付。

## 怎样理解检查结果

“第1–100集写齐”“编号与名称检查通过”“编辑需要大修”可以同时成立。

工具只能检查其覆盖的结构事实；正文是否有重复解法、人物是否总在讲道理、反派是否站着等主角，需要[编辑审读](references/editorial-review.md)。不靠删几个词宣布去AI味完成。

库内没有预装的命名、原创度、导入和导出脚本。环境可提供工具，Agent也可在项目里补必要助手；实际未执行就不得冒称工具验证。生成Word后回读核对正文，排版和时长按实际验证范围说明。

## 旧项目与旧启动语句

原来的“按MANUAL_OUTLINE.md执行”“按MANUAL_RESTRUCTURE.md继续”“按MANUAL_WRITE.md执行”仍能使用。对应文件现在是分阶段入口，统一遵循SKILL.md和项目约定。

旧项目中的ALL_DONE、NEED_THEME等文件只作历史线索；应核对实际产物、最新授权和当前版本后续接。不要批量删标记或只改标记来宣告完成。

多会话协作只在已获授权时使用，先明确分工和可写文件。单纯执行或继续不代表允许启动其他代理、调用付费服务或发布私稿。
