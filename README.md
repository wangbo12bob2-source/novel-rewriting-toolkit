# 中文故事改写 Skill · Novel Rewriting Toolkit

面向中文小说与分集短剧的 Agent Skill：提炼原稿、重构故事、完成正文、审稿修订和导出交付。

由读取文件的 Agent 执行，不是独立生成程序，也不需要专用模型服务。保留上游“提炼→重构→写作”的方法，加入载体分流、内部试写、单元差异复核、人物状态和真正的正文审稿。

[正式入口](SKILL.md) · [中文使用说明](README_CN.md) · [English](README_EN.md) · [MIT许可证](LICENSE)

## 开始使用

将本仓库作为可读取的Skill目录，素材与成果放在单独项目目录。告诉Agent：

```text
读取SKILL.md。分析我提供的中文短剧DOCX，先给全稿分析和改写方向，暂不写正文。
```

已有方向和授权时：

```text
按SKILL.md继续已有项目，保留已选方向，人物、地名与关键道具更名。
完成全部正文并做自然表达修订；内部试写和审读完成后继续，不停在小样。
```

如果所在工具已安装并识别本Skill，也可使用其正常的Skill调用方式；入口名称为novel-rewriting-toolkit。仓库包含agents/openai.yaml元数据，不强制使用某个模型或特定会话工具。

## 工作流

1. 恢复项目约定：载体、题材体验、规模、保留与改动项、当前授权、交付形式。
2. 只读导入并阅读原稿，分清事实、编辑判断和新方案，记录拆分异常。
3. 设计新关系与因果，验证开篇理由、不同单元解法和终点，再展开正文。
4. 按自然故事段复核题材、人物、时间与物件，维护可接续状态。
5. 分层审稿，保留版本，修订后复查并回读导出结果。

用户已授权全稿时，试写和复核是内部步骤；已给出的授权不重复询问。用户只要求分析或小样时，不扩展到未授权的正文。

## 这一版解决什么

- 小说和短剧按需读取规则，不再把固定合章比例、网文字数和创世级终点套给所有素材。
- “去AI味”先处理场面重复、人物口吻和说教，再改措辞；取消短句配额、普通字和标点的全局禁用。
- 审核开篇是否成立、单元是否可互换、反派是否持续行动、伏笔是否在正文实际回答。
- 分别报告写齐范围、结构检查与编辑结论。结构通过的完整稿仍可能需要大修。
- 最新范围与当前版本有明确入口，修订追查受影响后文，导出不能混用旧版本。

这些改进来自一次百集短剧实践中的失误与审稿；它们不是观众测试结果或模型质量排名。私有原稿和实际正文未放入仓库。维护者可使用[自编回归题](references/regression-cases.md)进一步验证。

## 工具与限制

核心是Markdown指令，不附带Python改写引擎、模型API、DOCX解析器、命名检查器或导出器。Agent可以调用当前环境已提供的工具，或在项目中编写必要的小助手；存在且实际执行后才能报告验证通过。

TXT、Markdown和DOCX需由环境中适用的工具读取；读取不了就说明缺项。Python仅在选用相应辅助工具时需要。Word导出须回读全部正文，时长和制作可行性仍需读本及制作评估。

更名和重写不能提供原创百分比、AI检测通过率或无争议保证。Skill不替用户上传素材、发布作品、启动其他代理或调用付费服务；相关操作需要已有授权。

仓库仅提交指令和可公开参考。输入、正文、版本、样本、运行记录和密钥保留在独立项目中；.gitignore是辅助防线，发布前仍需检查待提交文件。

## 维护与验证

修改时同时核对旧手册和润色引用，不能只加一句新版优先。验证入口结构和本地链接，再按回归题检查实际行为；格式验证不等于创作质量验证。

本分叉继续保留上游Git历史和MIT许可证，旧版手册可从Git历史回看。自然表达方法参考Humanizer-zh及原仓库中的写作实践，已按虚构叙事重新收敛；不将说明性文章的规则直接套给角色。
